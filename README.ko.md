## 버그를 되감고, 그 순간을 표시하고, 상태를 AI에게 전달하세요

**CapturePack은 기본 30초의 순환 리플레이를 사람과 AI가 함께 읽을 수 있는 구조화된
증거로 바꿉니다.**

문제가 생긴 뒤 단축키를 누르고, 그 일이 실제로 벌어진 프레임까지 되감으세요.
망가진 곳에 상자를 그리고 무슨 뜻이었는지 적은 다음 저장하면 됩니다. 팩에는
리플레이, 시간에 따라 기록된 데스크톱의 창·컨트롤 좌표, 그리고 당신의 주석이
함께 담깁니다. AI가 픽셀만 보고 나머지를 추측하지 않아도 됩니다.

**객체 선택은 정지 이미지 기능입니다.** 스크린샷을 찍으면 커서 아래의 실제
컨트롤을 그대로 클릭할 수 있습니다. CapturePack은 그 컨트롤의 이름, 역할,
AutomationId, 프로세스를 기록하고, 브라우저에서는 보이던 페이지 전체까지
기록합니다. 리플레이는 같은 것을 정직하게 제공할 수 없기 때문에
([그 이유](#객체-선택이-정지-화면의-몫인-이유)) 영상에는 직접 그린 상자가
남습니다.

저장된 팩은 사용자가 캡처한 것과 그대로 일치합니다. 영상 팩에는 리플레이, 프레임,
주석, 객체 맥락, 이벤트 타임라인이 함께 담기고, 이미지 팩에는 명시적으로 캡처한
정지 이미지와 주석, 객체 맥락이 담깁니다. 어느 쪽이든 `viewer.html`을
더블클릭하면 CapturePack을 설치하거나 서버를 띄우지 않고 오프라인에서 살펴볼 수
있습니다. 팩은 AI도, 계정도, 클라우드 서비스도 없이 열리는 로컬 폴더 그대로입니다.

🌐 **[capturepack.dev](https://capturepack.dev)** · [다운로드](https://github.com/r2cuerdame/capturepack/releases/latest)

현재 공개 Windows 릴리스: **CapturePack 0.4.0**. 이제 팩은 화면 하나가 아니라
모든 화면을 적습니다. 타임라인에는 커서와 창이 어떻게 움직였는지가 남습니다.
무엇을 입력했는지는 결코 남지 않습니다.

있습니다. 그렇게 남긴 증거는 그대로 AI가 읽을 구조화된 데이터로 저장됩니다.

## 사용 흐름

1. **되감기** — 라이브 녹화가 켜진 기본 상태에서 버그가 난 뒤 `Ctrl+Alt+C`를
   누르고, 멈춰 선 리플레이를 훑어 UI가 잘못돼 있던 프레임으로 이동하세요.
   리플레이 길이는 1–60초로 설정할 수 있습니다.
2. **표시하기** — 오른쪽 드래그로 망가진 곳에 상자를 그리고 무슨 뜻이었는지
   적으세요. 상자에는 수명이 있어서, 그것이 설명하는 순간에 맞춰 나타났다가
   사라집니다.
3. **또는 정지 화면을 캡처하고 객체를 고르기** — 스크린샷 단축키를 누르면 객체
   선택이 커서 아래의 실제 컨트롤을 강조합니다. 한 번 클릭하면 접근성 이름,
   컨트롤 유형, AutomationId, 프로세스, 관측 경계가 기록되고, 컨트롤 정보를 얻지
   못하면 창이 대체 대상으로 남습니다. 브라우저에서는 페이지 자체도 함께
   남습니다. 눈에 보이던 모든 요소가 역할, 사각형, 텍스트와 함께 기록됩니다.
   입력한 값, 비밀번호 입력란, 숨겨져 있던 것은 의도적으로 제외하며, 무엇을
   빼놓았는지 페이로드가 목록으로 밝히기 때문에 비어 보이는 폼이 가려진 결과라는
   사실을 읽는 사람이 알 수 있습니다.
4. **구조화된 맥락 전달** — 폴더를 다른 개발자에게 넘기거나 ChatGPT, Claude,
   Codex, Cursor, Gemini에 그대로 넣거나, 내장된 읽기 전용 MCP 서버로 연결된
   AI가 읽게 하세요.

### 객체 선택이 정지 화면의 몫인 이유

리플레이에서 고를 가치가 없어서가 아니라, 거기서는 *절반만* 고를 수 있기
때문입니다.

창 좌표는 쌉니다. CapturePack은 1초에 약 100번 표본을 남기므로 어느 프레임에서든
어떤 창이 어디 있었는지 답할 수 있습니다. 창 안의 **컨트롤**을 훑는 일은 싸지
않습니다. 평범한 책상에서 Chromium 창을 한 번 훑는 데 326 ms가 드는 반면, 나머지
전부를 합치면 13.9 ms입니다. 그래서 녹화 중 도는 트래커는 CPU 3% 듀티에 맞춰
속도를 늦추고 그 창들은 건너뜁니다. 그 결과는, 캡처한 바로 그 순간에는 브라우저
안의 버튼을 내어주지만 앞뒤 1초에서는 브라우저 창만 내어주면서, 지금 어느 쪽을
쥐고 있는지 화면에는 아무 표시도 없는 기능이었습니다.

정지 화면에는 그런 분열이 없습니다. 순간은 하나뿐이고, 그 순간에 전체 순회가
돌고, 데스크톱의 모든 컨트롤이 후보가 됩니다. 그래서 정밀함은 그쪽으로 갑니다.

영상도 무엇이 있었는지는 여전히 *기록합니다*. 시간에 따른 창·컨트롤 좌표는 팩의
맥락 타임라인에 담겨 AI가 읽습니다. 다만 그것을 클릭하라고 권하지 않을 뿐입니다.

### 객체 정보의 출처

- **Windows UI Automation(기본 내장):** 접근성 컨트롤 이름, 의미 있는 컨트롤
  유형, AutomationId, 프로세스/창 식별 정보, 그리고 앱이 제공하는 경우 관측 경계.
- **Chrome DOM(선택 프리뷰 확장):** 사용자가 명시적으로 고른 요소의 selector,
  역할, 텍스트와 URL — CapturePack 툴바 아이콘을 누른 뒤 요소를 클릭하면 됩니다.
  iframe 안에서도 동작하고, 그 선택에 한해서만 페이지를 읽으며, DOM을 계속
  전송하지 않습니다. 설정 › 플러그인 › Chrome DOM에 피커가 마지막으로 한 일이
  표시되므로, 선택이 도착하지 않았다면 그 이유를 알 수 있습니다.
  **CapturePack 아이콘을 한 번 클릭해 브라우저에 권한을 주세요.** 그다음부터
  Chrome에서는 아무것도 누르지 않습니다. 평소 쓰던 캡처 단축키가 보이던 페이지를
  함께 가져옵니다. 이 한 번의 허용이 필요한 이유는 Chrome이 전역 단축키를 결코
  볼 수 없기 때문입니다. Chrome은 Chrome 안에서 일어난 클릭이거나 사용자가
  허용한 확장에만 페이지를 넘겨줍니다. 허용하기 전까지는 아무것도 보관하지 않고
  (설치 시 권한 경고도 뜨지 않습니다), `chrome://extensions`에서 언제든 회수할 수
  있습니다. 허용 없이 만들어진 팩은 페이지를 담지 않고, 그 사실을 그대로
  밝힙니다.
- **HWND 창 대체 경로:** 사용할 수 있는 하위 컨트롤이 없으면 CapturePack은
  컨트롤을 지어내는 대신 실제 창과 관측된 위치를 기록합니다.

### 한 장이면 충분할 때

`Ctrl+Alt+S`를 누르면 영역 캡처가 열립니다. 기본은 영역 드래그이며, 상단의
**전체 화면 캡처** 버튼은 모든 모니터를 하나로 묶은 가상 데스크톱 전체를
명시적으로 캡처합니다. 결과물은 같은 맥락 편집기에서 원본 100%(지나치게 큰
데스크톱이라면 지원되는 가장 가까운 배율)로 열리고 화면을 끌어 이동할 수
있지만, 팩은 이미지로 선언되며 리플레이 파일을 담지 않습니다. 영역 팩은 선택한
픽셀과 크롭 위치 메타데이터만 저장합니다. 숨겨진 전체 화면 이미지나 다른 모니터
이미지를 따로 보관하지 않습니다.

## 왜 필요한가

- **스크린샷은 픽셀을 남깁니다.** 그 프레임 이전에 벌어진 일은 사라집니다.
- **영상은 움직임을 남깁니다.** 의도와 구조는 사라집니다.
- **CapturePack은 맥락을 남깁니다.** 리플레이와 그 시간 동안 기록된 창 좌표,
  정지 화면에서 고른 객체, 주석, 그리고 실제로 캡처된 상태까지 함께 남습니다.

## 되감기부터

버그는 이미 지나갔나요? 라이브 녹화가 켜져 있다면(기본값) CapturePack은 최근
리플레이를 메모리에 준비해 둡니다. 문제가 생긴 *뒤에* `Ctrl+Alt+C`를 누르고,
마우스 휠로 **시간을 거슬러** 망가진 프레임까지 되감으세요. 라이브 녹화를 끄면
아무것도 기록되지 않으며, 단축키를 눌러도 녹화가 꺼져 있다고 알려줍니다.

## 구조화된 맥락이 담는 것

정지 이미지에 남긴 주석은 사각형 이상을 식별할 수 있습니다. 영상의 주석은 직접
그린 상자와, 각 상자가 설명하는 순간입니다.

- **대상 식별 정보:** 애플리케이션이 제공하는 경우 UIA 이름, 컨트롤 유형(컨트롤의
  의미 있는 역할), AutomationId, 프로세스나 창 식별 정보. 선택 사항인 Chrome DOM
  선택은 대신 selector, 역할, 텍스트, URL을 담습니다.
- **시간 속의 캡처된 상태:** 선택한 시점, 그때의 디스플레이, 그 순간에 관측된
  경계.
- **시각적·서술적 증거:** 원본 미디어, 편집 가능한 주석, 생성된 뷰와 리포트.
  영상 팩에는 키프레임, 타임라인, 그리고 그 시간 동안 기록된 창 좌표가 더해집니다.

이 맥락은 평범한 폴더에서 그대로 읽을 수 있습니다. 연결된 AI라면 앱의 **읽기 전용
MCP 서버**를 써서 이렇게 시작할 수도 있습니다. *"최신 CapturePack을 분석해줘."*

## 팩의 구성

팩은 평범한 **폴더**입니다. 열어볼 수 있고, 고칠 수 있고, 숨기는 것이 없습니다.
ZIP(`.capturepack`)은 공유하고 싶을 때만 만들어집니다.

영상 팩에는 다음이 들어갈 수 있습니다.

```
CapturePack_2026-07-27_143052/
├── replay.mp4               # 원본 증거(또는 대체본 replay.webm)
├── replay_annotated.webm    # 선택 파생본; 매니페스트에 선언된 경우에만
├── snapshot.png             # 캡처한 프레임(원본)
├── annotations.json         # 진짜 원본: 상자, 수명, 번호, 블러
├── timeline.json            # 영상 팩: 기계가 읽는 이벤트 로그
├── viewer.html              # 더블클릭으로 여는 오프라인 뷰; 서버 불필요
├── report.md                # 당신의 설명, LLM이 바로 읽을 형태
├── manifest.json            # 포맷 버전, 목록
├── README.md                # 사람이 가장 먼저 읽는 문서
├── skills/                  # AI를 위해 구조화한 맥락(MCP 없이도 동작)
└── plugins/                 # 확보된 경우의 UI 객체 메타데이터
```

이미지 팩은 의도적으로 다릅니다.

```
CapturePack_2026-07-27_143052/
├── snapshot.png             # 명시적으로 고른 영역 또는 전체 가상 데스크톱
├── annotations.json         # 이미지 주석
├── viewer.html              # 더블클릭으로 여는 오프라인 뷰; 서버 불필요
├── report.md · README.md
├── manifest.json            # capture_kind: image
├── skills/                  # 이미지 전용 맥락; 타임라인 스킬 없음
└── plugins/                 # 선택적인 객체 메타데이터
```

이미지 팩은 `capture_kind: "image"`와 함께 영역인지 전체 화면인지를 기록합니다.
리플레이도 `timeline.json`도 없습니다. 영역 이미지는 크롭 바깥의 픽셀을 저장하지
않으면서 크롭이 어디에서 왔는지만 기록합니다.
객체 메타데이터 역시 있으면 담는 증거입니다. 애플리케이션이 쓸 만한 UI 객체를
제공하지 않으면, 팩은 맥락을 지어내는 대신 그 사실을 그대로 말합니다.

구현보다 명세가 중요합니다. 어떤 언어로도 CapturePack 파일을 만들 수 있습니다. [SPEC.md](SPEC.md)를 참고하세요.

## MCP — 캡처와 대화하기

앱에는 선택 사항인 읽기 전용 [MCP](https://modelcontextprotocol.io) 서버가 있으며,
기본적으로 `http://127.0.0.1:39393/mcp`(localhost 전용)에서 활성화되어 자동으로
시작됩니다. 설정 → MCP에서 즉시 중지하거나 자동 시작을 끌 수 있습니다. 서버는
사용자가 이미 저장한 CapturePack만 읽으며, 이미지나 영상 캡처를 시작할 수는
없습니다.

AI는 `capturepack_history`로 이미지·영상 기록을 훑거나 검색한 뒤 고른 id로
`capturepack_open`을 호출할 수 있습니다. `capturepack_latest`는 여전히 가장 최근
팩으로 가는 지름길입니다.

```
claude mcp add --transport http capturepack http://127.0.0.1:39393/mcp
```

도구 목록, 클라이언트 설정, 세부 옵션은 [docs/MCP.md](docs/MCP.md)에 있습니다.

## 설정과 진단

- 설정 → 캡처에서 영상(`Ctrl+Alt+C`)과 이미지(`Ctrl+Alt+S`) 단축키를 각각
  설정하고, 리플레이 길이와 5–30 fps 캡처 속도를 지정할 수 있습니다.
- 정보 → **로그 폴더 열기**를 누르면 크기가 제한된 로컬 실행 진단 로그가 열립니다.
  로그는 자동으로 업로드되지 않습니다.

## 상태

**현재 공개 Windows 다운로드는 0.4.0입니다.** CapturePack은 아직 초기 단계
프로젝트이므로, 문제를 보고할 때는 원본 팩을 보관해 두세요. 제품이 향하는 방향은
[GOAL.md](GOAL.md)에, 다음에 올 것은 [ROADMAP.md](ROADMAP.md)에 있습니다.

알려진 한계: 디스플레이별 영상/맥락 PTS 정렬은
[issue #89](https://github.com/r2cuerdame/capturepack/issues/89)에서 계속 측정
중입니다. CapturePack은 애매한 타이밍 증거를 전역 오프셋 값으로 덮어 감추는 대신
있는 그대로 기록합니다.

## 공유 전 개인정보 확인

화면 픽셀, 창 제목, 접근성 이름 — Chrome DOM을 쓴다면 selector, 역할, 텍스트,
URL까지 — 에는 민감한 정보가 들어 있을 수 있습니다. CapturePack은 캡처와 객체
맥락을 이 컴퓨터에 두고, 캡처·텔레메트리·충돌 보고서를 업로드하지 않습니다. 앱이
바깥으로 보내는 유일한 요청은 설정 → 일반에서 끌 수 있는 선택적인 GitHub 릴리스
업데이트 확인뿐입니다.

블러는 비파괴 방식입니다. 주석이 렌더링된 결과물은 보호하지만, 전체 팩 안의
`snapshot.png`와 원본 리플레이는 가려지지 않은 상태로 남습니다. 팩을 공유하기 전에
내용을 확인하고, 원본 미디어에 비공개로 남아야 할 정보가 있다면 팩 전체를
공유하지 마세요.
