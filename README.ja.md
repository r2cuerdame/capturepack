## バグを巻き戻し、壊れた箇所に印を付け、その状態をAIへ

**CapturePackは、既定30秒のローリングリプレイを、人とAIが読める構造化された証拠に変えます。**

何かがおかしくなった後にホットキーを押し、それが起きたフレームまで巻き戻します。
壊れた箇所を囲み、意図を書いて保存するだけです。パックにはリプレイ、時間を通じて
記録されたデスクトップのウィンドウとコントロールの座標、そしてあなたの注釈が
収められます。AIにピクセルだけからすべてを推測させる必要はありません。

**Object Pickは静止画の機能です。** スクリーンショットを撮れば、カーソル下にある
実際のコントロールをそのままクリックできます。CapturePackはその名前・ロール・
AutomationId・プロセスを記録し、ブラウザーであれば表示されていたページ全体も
記録します。リプレイで同じことを誠実に提供することはできません
（[理由はこちら](#オブジェクト選択が静止画のものである理由)）。ですから動画では、
あなた自身が描いたボックスがその役目を担います。

保存されるパックは、ユーザーがキャプチャしたものと一致します。動画パックは
リプレイ、フレーム、注釈、オブジェクト情報、イベントのタイムラインをまとめ、
画像パックは明示的に撮った静止画、注釈、オブジェクト情報を収めます。
`viewer.html`をダブルクリックすれば、CapturePackをインストールせず、サーバーも
立てずに、どちらの種類もオフラインで確認できます。パックはAIもアカウントも
クラウドサービスも必要としない、ローカルで開かれたフォルダーのままです。

🌐 **[capturepack.dev](https://capturepack.dev)** · [ダウンロード](https://github.com/r2cuerdame/capturepack/releases/latest)

現在公開中のWindows版: **CapturePack 0.5.0**。履歴からレビュー済みの
**共有用コピー**（`.share.zip`）を作成できます。含まれるメディアはレビュー済みの注釈付き
PNG静止画だけで、生成されたREADME、オフラインビューアー、最小限のインベントリが
付属します。原本、すべての動画、構造化コンテキストは除外されます。通常のフルZIP
（`.zip`）には引き続き原本が含まれます。

## ワークフロー

1. **巻き戻す** — ライブ録画がオン（既定）の状態で、不具合の後に`Ctrl+Alt+C`を
   押し、静止したリプレイをスクラブしてUIが壊れていたフレームまで戻ります。
   リプレイの長さは1〜60秒で設定できます。
2. **印を付ける** — 壊れた箇所を右ドラッグで囲み、意図を書き添えます。ボックスには
   表示時間があるので、それが説明する瞬間に合わせて現れ、そして消えます。
3. **あるいは静止画を撮ってオブジェクトを選ぶ** — 画像キャプチャのホットキーを
   押すと、Object Pickがカーソル下にある実際のコントロールをハイライトします。
   クリックひとつで、そのアクセシブル名、コントロール種別、AutomationId、
   プロセス、観測済み境界が記録されます。コントロールの情報が得られないときは、
   ウィンドウがフォールバックとして残ります。ブラウザーではページそのものも
   パックに残り、見えていたすべての要素がロール・矩形・テキストとともに保存
   されます。入力した文字列、パスワード欄、隠れているものは意図的に除外され、
   ペイロードには除外した内容が記録されます。空に見えるフォームが伏字処理の
   結果であることが、読み手にきちんと伝わるためです。
4. **構造化コンテキストを渡す** — フォルダーをそのまま別の開発者に渡すか、
   ChatGPT、Claude、Codex、Cursor、Geminiに投げるか、内蔵の読み取り専用MCP
   サーバー経由で、接続したAIに読ませます。

### オブジェクト選択が静止画のものである理由

リプレイの中で選ぶ価値がないからではありません。*半分しか*選べないからです。

ウィンドウの座標は安価です。CapturePackは毎秒およそ100回サンプリングするので、
どのフレームでどのウィンドウがどこにあったかを答えられます。しかしウィンドウの中の
**コントロール**を歩き回るのは安くありません。ふつうのデスクトップでChromiumの
ウィンドウを一巡すると326ミリ秒かかり、それ以外のすべてを合わせた13.9ミリ秒とは
桁が違います。そのため録画中に走るトラッカーはCPU使用率3%に収まるようペースを
落とし、Chromiumは対象から外します。そうして出来上がるのは、キャプチャした瞬間
だけはブラウザー内のボタンを差し出し、その前後1秒ではブラウザーのウィンドウしか
差し出さない機能でした。しかも画面上には、いま自分がどちらを手にしているのかを
示すものが何もありません。

静止画にこの分裂はありません。ひとつの瞬間だけを対象に完全な走査を走らせられる
ので、デスクトップ上のあらゆるコントロールが選択の対象になります。だから精度は
そちらへ振り向けられました。

動画も、そこに何があったかを*記録*し続けます。時間を通じたウィンドウと
コントロールの座標はパックのコンテキストタイムラインに残り、AIが読めます。
なくなったのは、それをクリックするよう誘う振る舞いだけです。

### オブジェクト情報の出所

- **Windows UI Automation（内蔵）:** アクセシブル名、意味的なコントロール種別、
  AutomationId、プロセス/ウィンドウ情報、そしてアプリが公開していれば
  観測済み境界。
- **Chrome DOM（任意のプレビュー拡張）:** 明示的に選んだ要素のselector、role、
  text、URL。CapturePackのツールバーアイコンをクリックしてから、要素をクリック
  します。iframeの中でも動作し、その選択のときだけページを読み、DOMを流し続ける
  ことはありません。設定 → プラグイン → Chrome DOMにピッカーの直近の動作が
  表示されるので、選択が届かなかったときもその理由がわかります。
  **CapturePackのアイコンを一度クリックして、ブラウザーで許可してください。**
  その後はChrome側で何も押す必要はありません。いつものキャプチャのホットキーが、
  表示中のページを一緒に持ってきます。この一度きりの許可が必要なのは、Chromeが
  グローバルホットキーを見ることはないからです。Chromeがページを拡張機能へ渡すのは、
  Chromeの中で行われたクリックに対してか、ユーザーが許可した拡張機能に対してだけ
  です。許可するまで何も保持されず（インストール時に権限の警告も出ません）、
  `chrome://extensions`からいつでも取り消せます。許可のないまま書き出された
  パックはページを含まず、その旨を明記します。
- **HWNDウィンドウのフォールバック:** 子コントロールが得られない場合も、
  CapturePackはコントロールを捏造せず、実際のウィンドウと観測済みの座標を
  記録します。

### 1枚だけ必要な場合

`Ctrl+Alt+S`で範囲キャプチャを開きます。既定は範囲のドラッグで、上部の
**全画面キャプチャ**ボタンは仮想デスクトップ全体を明示的に撮ります — すべての
モニターが1枚の画像になります。結果は同じコンテキストエディターでネイティブ100%
（極端に大きいデスクトップでは対応可能な最も近い倍率）で開き、パンできますが、
パックは画像として宣言され、リプレイのファイルは含みません。範囲パックは選択された
ピクセルと切り抜き位置のメタデータだけを保存し、隠れた全画面画像や別モニターの
画像を保持することはありません。

## なぜCapturePackなのか

- **スクリーンショットはピクセルを残します。** そのフレームより前に何が起きたかは
  失われます。
- **動画は動きを残します。** 意図と構造は失われます。
- **CapturePackはコンテキストを残します。** リプレイとその間に記録されたウィンドウ
  座標、静止画で選んだオブジェクト、注釈、そして実際にキャプチャされた状態です。

## まず巻き戻す

バグはもう起きてしまった後ですか。ライブ録画がオン（既定）なら、CapturePackは
直近のリプレイをメモリー上に用意しています。何かがおかしくなった*後*に
`Ctrl+Alt+C`を押し、マウスホイールで**時間をさかのぼって**壊れたフレームまで
戻ってください。ライブ録画をオフにすると何も記録されず、ホットキーは録画が
オフであることを伝えます。

## 構造化コンテキストが語ること

静止画に付けた注釈は、ただの矩形以上のものを特定できます。動画の注釈は、あなたが
描いたボックスと、それぞれが説明する瞬間です。

- **対象の識別情報:** アプリケーションが公開していれば、UIA名、コントロール種別
  （そのコントロールの意味的な役割）、AutomationId、プロセスまたはウィンドウ情報。
  任意のChrome DOMの選択であれば、代わりにselector、role、text、URLを持ちます。
- **時間の中でキャプチャされた状態:** 選択した瞬間、それが表示されていた
  ディスプレイ、そしてその瞬間に観測された境界。
- **視覚的・記述的な証拠:** 元のメディア、編集可能な注釈、生成されたビューと
  レポート。動画パックにはさらにキーフレーム、タイムライン、そしてその間に
  記録されたウィンドウ座標が加わります。

このコンテキストは、ただのフォルダーからそのまま読めます。接続したAIはアプリの
**読み取り専用MCPサーバー**を使い、*「最新のCapturePackを分析して」*から始める
こともできます。

- 生成されるパックのドキュメント（`viewer.html`、`README.md`、`report.md`、`skills/`）は独自の言語設定に従わせることができます。あなた自身が書いた説明が翻訳されることはありません。

## 原則

ローカルファースト · オフラインファースト · オープン形式 · プラグインベース · クラウドなし · ログインなし · データベースなし · AI依存なし · ベンダーロックインなし。

生成されたCapturePackは、いつまでも読めるままであるべきです。

## 意図的に行わないこと

CapturePackは製品の境界を意図的に厳格に定めています:

- **クラウドサービス、必須アカウント、隠れたテレメトリの排除:** CapturePackは完全にローカルかつオフラインで動作します。テレメトリ、行動追跡、クラッシュレポートが外部に送信されることはありません。唯一の外部接続は任意のGitHub Releases更新確認のみです（設定 → 一般で無効化可能）。
- **キーロガー動作の排除:** 再生クロックに合わせてマウス座標、クリック、ウィンドウ操作を記録します。キー入力を監視または記録することは絶対にありません（`input.key.*`は予約・禁止されています）。
- **範囲キャプチャ時の隠れた背景ピクセルの排除:** 範囲スクリーンショット（`Ctrl+Alt+S`）は、選択された切り抜きピクセルと配置メタデータのみを保存します。画面全体や未選択モニターのピクセルを密かに保持することはありません。
- **動画録画中のリアルタイムなオブジェクト選択の排除:** 録画中にアクセシビリティツリーを巡回するとCPU負荷が膨大になります。動画録画はウィンドウの配置変化を記録しますが、コントロール単位のインタラクティブなオブジェクト選択は静止画専用です。
- **予告のない自動削除の排除:** 保持ポリシーはユーザーが明示的に設定した容量や日数に従います。手動削除時はファイルを完全に抹消せず、ごみ箱へ安全に移動します。
- **未確認の自動認証情報除去の排除:** ぼかしは非破壊的な視覚的マスキングです。秘密情報が自動で完全に消去されると過信せず、共有前に静止画を目視で確認してください。
- **コアへの外部イシュートラッカーの抱え込み排除:** コアアプリはJira、GitHub、Linearなどの外部起票コードを直接抱え込みません。外部連携は保存後アクションプラグインやWebhookスクリプトに委ねられます。

## CapturePackの中身

パックはただの**フォルダー**です — 閲覧でき、編集でき、正直です。フル配布用コピーは
通常のZIP（`.zip`）で、元の証拠をそのまま含みます。履歴ではレビュー済みの
**共有用コピー**（`.share.zip`）も用意されます。含まれるメディアはレビュー済みの注釈付き
PNG静止画だけで、生成されたREADME、オフラインビューアー、最小限の閉じた
インベントリが付属します。

動画パックに含まれうるもの:

```
CapturePack_2026-07-27_143052/
├── replay.mp4               # オリジナルの証拠（replay.webm になる場合あり）
├── replay_annotated.webm    # 任意の派生ビュー。マニフェストで宣言された場合のみ
├── snapshot.png             # キャプチャしたフレーム（オリジナル）
├── annotations.json         # 真の出典: ボックス、表示時間、番号、ぼかし
├── timeline.json            # 動画パック: 機械可読なイベントログ
├── viewer.html              # ダブルクリックで開くオフラインビュー。サーバー不要
├── report.md                # あなたの説明。LLMがそのまま読める形
├── manifest.json            # 形式バージョン、収録物の一覧
├── README.md                # 人が最初に読むドキュメント
├── skills/                  # AI向けに構造化されたコンテキスト（MCPなしでも機能）
└── plugins/                 # 取得できた場合のUIオブジェクトのメタデータ
```

画像パックは意図的に異なります:

```
CapturePack_2026-07-27_143052/
├── snapshot.png             # 明示的に撮った範囲、または仮想デスクトップ全体
├── annotations.json         # 画像の注釈
├── viewer.html              # ダブルクリックで開くオフラインビュー。サーバー不要
├── report.md · README.md
├── manifest.json            # capture_kind: image
├── skills/                  # 画像専用のコンテキスト。タイムラインのskillはなし
└── plugins/                 # 任意のオブジェクトのメタデータ
```

画像パックは`capture_kind: "image"`と、範囲か全画面かのスコープを記録します。
リプレイも`timeline.json`もありません。範囲画像は、切り抜きの外側のピクセルを
保存することなく、その切り抜きがどこから来たのかを記録します。
オブジェクトのメタデータもまた任意の証拠です。アプリケーションが使えるUI
オブジェクトを公開していなければ、パックはコンテキストを捏造せず、その事実を
記します。

どの実装よりも仕様が重要です — CapturePackファイルはどの言語からでも生成できます。[SPEC.md](SPEC.md)を参照してください。

## プラグインと保存後アクション

設定 → プラグインで2種類のプラグイン機能を分離して管理します:

1. **時間軸コンテキストプロバイダー (Temporal Context Providers):** 録画・キャプチャ中にタイムスタンプ付きのメタデータを提供するプラグイン（Windows UI AutomationやChrome DOM拡張など）。詳細は[docs/temporal-provider-api.md](docs/temporal-provider-api.md)を参照してください。
2. **保存後アクション (After Save Actions):** パックがディスク上に安全に保存された後に順次実行される自動化パイプライン（バックグラウンドでの動画レンダリング完了後にも実行可能）。ローカルスクリプトの実行やHTTP Webhook送信が可能です。分離が徹底されており、アクションのハングや失敗によって保存済みパックが破損したりUIが停止したりすることはありません。WebhookのシークレットはWindows DPAPI（`safeStorage`）で暗号化され、ループバック以外の平文HTTPエンドポイントは拒否されます。

## MCP — キャプチャと対話する

アプリには任意の読み取り専用[MCP](https://modelcontextprotocol.io)サーバーが
同梱され、既定で`http://127.0.0.1:39393/mcp`（localhostのみ）で有効・自動起動
します。設定 → MCPから直ちに停止したり、自動起動を無効にしたりできます。読むのは
ユーザーがすでに保存したCapturePackだけで、画像や動画のキャプチャを開始することは
できません。

AIは`capturepack_history`を呼んで画像・動画の記録を一覧・検索し、選んだidを
`capturepack_open`に渡せます。`capturepack_latest`は最新のパックへの近道として
残っています。

```
claude mcp add --transport http capturepack http://127.0.0.1:39393/mcp
```

ツール、クライアント設定、各種設定は[docs/MCP.md](docs/MCP.md)へ。

## 設定と診断

- 設定 → キャプチャで、動画（`Ctrl+Alt+C`）と画像（`Ctrl+Alt+S`）のショートカット、
  リプレイの長さ、5〜30 fpsのキャプチャレートを個別に設定できます。
- 情報 → **ログフォルダーを開く**で、サイズ上限付きのローカルな実行診断を開けます。
  ログが自動でアップロードされることはありません。

## インストールとビルド

### ビルド済みWindowsインストーラー

[GitHub Releases](https://github.com/r2cuerdame/capturepack/releases/latest)から最新のインストーラーをダウンロードしてください:

1. `CapturePack-Setup-0.5.0.exe`と`SHA256SUMS.txt`をダウンロードします。
2. PowerShellでチェックサムを確認します:
   ```powershell
   Get-FileHash CapturePack-Setup-0.5.0.exe -Algorithm SHA256
   ```
3. インストーラーを実行します。OSSコード署名の申請中であるため、Windows SmartScreenの警告が表示される場合があります: **詳細情報** → **実行**をクリックしてください。

### ソースコードからのビルド

要件:
- Windows 10/11 (64-bit)
- [Node.js](https://nodejs.org/) `>= 22.12.0` (LTS推奨)
- npm `>= 10.9.0`

```powershell
# リポジトリのクローン
git clone https://github.com/r2cuerdame/capturepack.git
cd capturepack/core

# 固定バージョンの依存関係をインストール
npm ci

# ローカル開発モードで起動
npm run dev

# リリース候補検証ゲートを実行 (全自動テスト、型チェック、ビルド、スモーク)
npm run qa:rc
```

プロジェクトですので、問題を報告する際は元のパックを保管しておいてください。
プロダクトの目指す方向は[GOAL.md](GOAL.md)を、今後の予定は[ROADMAP.md](ROADMAP.md)を
参照してください。

既知の制限事項: ディスプレイごとの動画/コンテキストPTS同期は
[issue #89](https://github.com/r2cuerdame/capturepack/issues/89)で測定を続けています。
CapturePackは曖昧なタイミング証拠を固定オフセット値で隠さず、ありのまま
記録します。

## 共有前のプライバシー確認

画面のピクセル、ウィンドウタイトル、アクセシブル名 — そしてChrome DOMを使った場合は
selector、role、text、URL — には、機密情報が含まれることがあります。CapturePackは
キャプチャとオブジェクト情報をこのマシンに保持し、キャプチャもテレメトリも
クラッシュレポートもアップロードしません。アプリからの唯一の外部リクエストは、
設定 → 一般で無効にできる任意のGitHub Releases更新確認だけです。

ぼかしは非破壊です。生成された注釈付きビューは保護しますが、フルパック内の
`snapshot.png`と元のリプレイは未編集のまま残ります。元のメディアや構造化された
コンテキストを非公開にする必要がある場合は、履歴 → **共有用コピー**を使い、
送信前に含まれる各静止画のプレビューを確認してください。
共有用コピーは、原本、すべての動画コンテナ、manifest、注釈、timeline、プラグインの
コンテキスト、生成されたパック文書を除外し、含まれるPNGをピクセルだけから正規化して
再エンコードします。それでも、レビュー済みの派生画像に未指定の秘密が残っていない
ことを保証するものではありません。
