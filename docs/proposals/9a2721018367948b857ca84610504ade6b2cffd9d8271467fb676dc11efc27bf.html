왜 필요한가
수정 건수만으로는 사람들이 계속 쓰는지 알 수 없습니다. 낮은 우선순위를 유지하면서 품질과 실제 이용을 같은 기준으로 확인하려는 안입니다.

기존 제안 한 건의 보완 자료입니다. 목표 수치는 기존 채택 댓글에서 가져왔고, 실측 DAU는 unknown입니다. 이 덱은 지침의 합의 상태를 변경하지 않습니다.

02 / 05 · 수익은 기본 KPI가 아님

측정 출처와 판정안

Pulse의 웹·앱 통계를 구분해 봅니다

DAU 측정안

그날 수신한 서로 다른 익명 식별자 수를 웹과 앱별로 확인합니다. 같은 식별자의 중복 수신은 한 번으로 셉니다.

목표 5 / 20 / 100은 앱 DAU로 판정하고 웹 DAU를 함께 보고하는 안을 권합니다. 두 식별자는 연결되지 않으므로 합계를 사람 수처럼 표시하지 않습니다.

기간 비교안

각 기간 마지막 완료된 7일의 일평균 앱 DAU를 비교합니다. 하루만 늘어난 수치로 달성했다고 하지 않습니다.

KST 기준 집계를 권합니다. 서버의 시간대·환경 구분이 확인되지 않으면 변환을 가정하지 않고 unknown으로 남깁니다.

추가 KPI 출처: 실제 패치 횟수는 공식 배포 이력, 누적 다운로드는 공식 배포 통계로 확인합니다. 기존 30일 무재설치 관찰도 유지하되, Pulse 신호만으로 통과 판정하지 않습니다.

앱 기준과 7일 평균은 측정 정의 제안이며 기존 목표 숫자를 바꾸지 않습니다. 실제 통계 조회 권한과 집계 기준은 아직 확인되지 않았습니다. 결측은 0으로 채우지 않습니다.

측정 근거와 한계

기준 소스의 앱·웹 수집기는 로컬 날짜에 하루 한 번 전송을 시도합니다. 요청 전에 시도 날짜를 저장하므로 전송 실패가 자동 보정되지 않습니다. 전송 시도는 수신 성공이나 사람이 사용한 증거가 아닙니다. 앱의 test/dev 자료는 production에서 제외해야 합니다. 식별자 수는 이용자 수의 대리지표이며 여러 기기, 저장소 초기화, 통신 실패로 중복·누락이 생길 수 있습니다. 새 추적이나 식별자 연결은 제안하지 않습니다.

04 / 05

효과 · 비용 · 위험 · 결정

기존 목표 묶음을 유지하는 안을 권합니다

효과: 수정 성과와 이용 성과를 구분하고, 이용이 늘지 않을 때 성능·안정성·사용자 의견을 먼저 살펴볼 근거를 얻습니다.

비용: 추가 비용 없음. 기존 제품·이정표 범위 유지. 기존 PC·구독·통계·필수 CI 한도 안에서 진행합니다. 실제 청구액과 잔여 한도는 unknown입니다.

위험: 이용 기준선이 없어 목표 달성을 예측할 수 없습니다. 누락된 통계를 추정하거나 횟수를 맞추려고 검사를 생략하지 않습니다. 유료 코드 서명을 도입하지 않습니다.

추천: 기존 채택안 유지.
목표와 추가 KPI를 보존하고, 확인된 실측을 나란히 보고합니다.

기존 댓글의 선택은 1번입니다. 같은 채택을 다시 요구하지 않습니다. 변경하려는 경우에만 기존 결정함에서 이어갑니다.

  1. 기존 목표 묶음 유지 — 추천. 현재 채택 댓글에 적힌 선택입니다.
  2. 기간 또는 측정 기준 조정. 바꾸는 항목과 이유를 남깁니다.
  3. 목표 확정 보류. 기존 버그·유지보수는 계속합니다.
  4. 직접 입력. 원하는 목표·기간·측정 기준을 자유롭게 적습니다.

2~4번은 변경 의사가 생겼을 때의 응답 형식입니다. 결정 기한은 unknown입니다. 지침 정본에는 목표가 아직 미정으로 남아 있으므로 댓글 입력과 합의 반영 상태를 구분합니다. 이 덱 자체는 승인이나 지침 변경이 아닙니다. 같은 결정의 새 제안을 늘리지 않고 기존 결정함에서 후속 입력을 기다립니다.
