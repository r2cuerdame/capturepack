Install

Download the installer and run it. CapturePack lives in the tray and starts with Windows. It is unsigned for now, so Windows may warn on first run — More info → Run anyway.

Nothing leaves your machine. There is no account, no cloud, and no telemetry.

Capture

CapturePack is already recording — the last 30 seconds of every screen, in a loop, overwritten as it goes. That is why you press the hotkey after the thing you want to show, not before.

Ctrl + Alt + C

The screen freezes and the editor opens on the moment you pressed it. Nothing is written to disk until you save.

Three gestures, no toolbar

  • Left click Select the window or control under the pointer. The box then follows it.
  • Right drag Draw a box anywhere. A description field opens as you release.
  • Wheel Travel back through the replay to the moment the bug happened.

A box picked off an object keeps following it for as long as it lives, so it stays on the thing it names even while that thing moves. Move the box by hand and it stops following — the rectangle you placed is the answer. Press Enter to save, ? for every shortcut.

What you get

A folder, not an archive — so you can open it, read it, and drop it anywhere. Zip it only when you send it.

CapturePack_2026-07-29_114804/
  • README.md what this is, for a person
  • report.md the annotations, in order, as sentences
  • snapshot.png the frame you pressed on, per screen
  • replay.webm the seconds before it, per screen
  • replay_annotated.webm the same replay with your boxes burned in
  • annotations.json the machine-readable source of truth
  • skills/ how to read all of the above, for an LLM
  • plugins/ the objects on screen: windows, controls, DOM elements

Give it to an AI

Drag the folder into ChatGPT, Claude, Cursor or Gemini and ask your question. The pack explains itself — skills/ tells the model what every file is and how the pieces relate.

Or connect over MCP and skip the dragging. CapturePack runs a read-only MCP server on your machine; point your client at it and say:

“Analyze the latest CapturePack.”

Browser context

With the extension connected, a click in the browser is stored as what you clicked — selector, role, text, URL — instead of the pixels it was drawn with. Settings → Integrations walks you through it in three steps:

  1. Press Open and copy the path. Your browser opens on its extensions page and the folder path is already on the clipboard.
  2. Turn on Developer mode, click Load unpacked, and paste with Ctrl+V.
  3. Press I did that — find it. CapturePack finds the ID your browser assigned and registers itself.

The extension reads a page only when you pick an element from it. It never streams the DOM, and it talks to nothing but CapturePack on your own machine.

Worth knowing

  • The hotkey is yours. Settings → Capture rebinds it if Ctrl+Alt+C is taken.
  • 30 seconds is a default, not a limit. Longer buffers cost memory; the setting says how much.
  • Every screen is captured, each at its own resolution, and every one of them is annotatable.
  • Nothing is lost by closing the editor. History reopens any past capture to re-annotate or re-render.

If something is wrong

  • The hotkey does nothing. Another app has claimed it. Rebind it in Settings → Capture.
  • A screen reports a low frame rate. A screen capture only makes a frame when the screen changes, so an untouched monitor delivers almost nothing and has lost nothing. The pack records both numbers so a reader can tell which happened.
  • Something else. Open an issue — and attach the pack. It was built for exactly this.
